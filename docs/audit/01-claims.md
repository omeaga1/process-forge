**Date:** 2026-09-17
**Commit base:** 9b567f6 (`main`)
**Scope:** `README.md`, `docs/**`, all package/app READMEs.
**Method:** every substantive factual claim was traced to the file that would have to
implement it. No code was changed by this phase.

Verdicts:
- **BUILT** — the code does what the doc says.
- **PARTIAL** — a real mechanism exists but is narrower, or differs materially, from the claim.
- **ABSENT** — nothing in the repo implements it.

Recommendations are advisory only; nothing was deleted or edited.

Counts: **74 claims audited — 39 BUILT, 20 PARTIAL, 15 ABSENT.**

## Five most significant ABSENT findings

1. **Rust/Wasm engine (A3, D4, D18, S5).** Claimed in 5 documents. Total Rust in the repo is 152 lines of Tauri shell; zero Wasm artifacts or toolchain. The engine is 508 lines of TypeScript. README.md:87 already says "(TypeScript)" — the other docs simply contradict it.
2. **CopilotKit / generative UI (A1, A2, A10, D15, S11).** An entire architecture document is built on it. No package depends on `@copilotkit/*`; the string appears in source exactly once, as a doc comment at `packages/protocol/src/agents.ts:34`. The real AI layer is 363 hand-rolled lines in `packages/canvas-ui/src/ai/llmClient.ts`.
3. **"Fixed random seeds" / deterministic reproducibility (D6).** `Math.random()` is called unseeded at `engine.ts:185` and `:261`, with non-zero default reject rates, and `simulateProcess` takes no seed. This is the one absent claim that is also a functional defect — it is cheap to fix and everything else (regression tests, reproducible OEE) depends on it.
4. **Security Tiers 2 and 3 (R6, R7, R11, A13, A14).** No KMS, Vault, Bedrock, Azure OpenAI, vLLM, Dockerfile, compose file, Helm chart, or TimescaleDB anywhere. Tier 1 (OS keychain) is real but overstated — keys are written to `localStorage` first, the Anthropic key never reaches the vault, and `get_secure_token` is never called (S3).
5. **The agentic loop and `query_unit_subagent` (A15, A17, A18, M5).** No propose→simulate→diagnose→refine cycle exists: each MCP tool is a standalone pure function, `llmClient.ts` has no tool-use plumbing, and `GraphProposalSchema` has zero consumers. `query_unit_subagent`, documented as "the dedicated machine-level Sub-Agent", is a `switch` with two real branches out of seven enum values and no model call at all.

Also worth flagging even though it is not ABSENT: **`diagnose_bottlenecks` (M2)** advertises mass/volume conservation auditing and queue-accumulation analysis. Neither exists; the "buffer capacity" figure it returns is `conveyorBuffers.length * 48`, a magic constant. That is the most misleading of the six tool descriptions after `query_unit_subagent`.
